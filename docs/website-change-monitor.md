# Webサイト更新監視（RSS不要）

RelayHarbor の「連携」→「＋ ガイド付きで追加」→「Webサイト更新監視」から設定できます。
**Relayサーバー v0.6.0 以上**が必要です。単にAndroidを更新するだけでは動きません。

## 登録する項目

1. **監視URL**: 公開されたHTTPSページ（例：`https://example.com/announcements`）
2. **通知先**: 「Web更新」「お知らせ」など任意のチャンネル名
3. **CSSセレクター（任意）**: 監視する領域。例：`main`、`#news`、`.updates`、`main article`
4. **チェック間隔**: 15分〜24時間。初期値30分。サイトの負荷を考慮して長めから始めてください。
5. **キーワード（任意）**: 変更後の監視範囲内に含まれる場合のみ通知

最初の成功したチェックではページ本文のハッシュを**基準値として保存するだけ**で通知しません。
以降は内容が変化したときだけ、変更部分の文字列・元ページリンクを含むリッチカードをRelayHarborに送ります。

## CSSセレクターの選び方

Chrome/EdgeのPCブラウザで監視サイトを開き、変更を知りたい箇所を右クリックして「検証」、
開発者ツールでその要素の `id` や `class` を確認します。

- `<main id="news">...` → `#news`
- `<div class="announcements">...` → `.announcements`
- ページ全体 → 未入力（ただし広告や時刻による誤通知が起きやすい）

指定した要素が見つからない場合は取得エラーとなり、前回の基準値を保護します。
CSSセレクターやURLを変更すると、次の取得時に**再度基準値を保存**します。

## 仕様・制限

- RelayサーバーからHTTP GETで取得できる**静的なHTMLテキスト**を比較します。JavaScriptで後から描画される内容、ログイン必須ページ、CAPTCHA/ボット対策サイト、画像の差分には対応しません。
- HTTPS/443の公開DNSホストのみ。IPアドレス・localhost・社内/家庭内ホスト、ユーザー名やパスワード付きURLは不可。
- リダイレクトは最大3回で都度ホストとDNSを検証、環境プロキシなし、接続タイムアウト6秒・全体12秒、応答本文は1MiBまで。DNSの事前検証だけではDNSリバインディングを完全には防げません。**信頼できる公開サイトのみ**監視してください。
- 監視件数はサーバーごとに最大50、チェック頻度は1件あたり15分以上。
- URL・セレクター・スケジュール・基準テキストとハッシュはRelayのSQLiteに保存されます。パスワードやログインCookieは保存しません。
- 監視設定は「設定をエクスポート/インポート」で移行できます。基準値自体はエクスポートしません。インポート先では初回チェックが新しい基準となります。
- 取得対象サイトの規約・robotsポリシーに従い、短すぎる間隔で大量のリクエストを送らないでください。
- Androidへの通知は既存のRelayイベント同期で届きます。**FCM即時プッシュは未実装**で、アプリがバックグラウンドにいる場合は同期が遅れることがあります。
- Relayサーバーは単一プロセス前提。複数ワーカーで同じSQLiteのポーラーを動かさないでください。

## 管理と更新

「連携」から有効/無効・URLとCSSセレクターの編集・「今すぐ確認」・削除を操作できます。
確認エラーや最終成功日時も連携カードに表示されます。

Relayサーバー（Synology NASなど）をGHCRイメージで運用している場合は、GitHub Actionsの
**Publish Relay Docker Image** が成功した後、サーバー側でデプロイスクリプトを実行してください。
例：`bash relay/scripts/nas-deploy.sh stable`（リポジトリルートから実行する場合）。
更新前にSQLiteのバックアップを取得し、`GET /healthz` が v0.6.0 以上であることを確認してください。
