# 連携先登録ウィザード (v0.6.3 candidate)

Androidアプリの **連携 → ＋ ガイド付きで追加** から開きます。
既存の「編集」画面、Webhookエンドポイント、RelayのDB・認証情報は変更しません。

## 手順

1. **サービスを選択**: 汎用Webhook、RSS/Atom、GitHub Actions、Dify、n8n、Lancers AI Scout。
2. **基本情報**: 連携先の名前、チャットの通知先チャンネル。RSSの場合は公開HTTPSフィードURLも指定。
3. **通知設定**: Webhookは最低スコアとキーワード、RSSは15分〜24時間の取得間隔とキーワード。
4. **内容を確認**: 登録内容と送信元の設定方法を確認し、「連携先を作成」。

入力途中で閉じても **端末内に下書きを自動保存** し、再開できます。
「下書きを破棄」で消去します。下書きにはトークンやAPIキーを保存しません。
登録エラーはウィザード上に表示され、設定を修正して再試行できます。

## 登録後のテスト

- **Webhook / GitHub Actions / Dify / n8n / Scout**:
  - 作成後の画面で専用Webhook URLをコピーします。
  - 一度しか表示されない **専用Bearerトークンをコピー** して送信元に登録してください。
  - 「テスト通知を送信」でRelay側のテストイベント登録を依頼し、連携先の状態とチャットを確認します。
  - テストイベントは **送信元アプリからの配信成功を保証するものではありません**。
    実際の外部サービスからもテストPOSTを実施してください。
- **RSS**:
  - 「今すぐ記事を取得」から取得を試し、チャットと連携一覧の最終取得・エラー状態を確認します。

送信元の登録が必要なサービスでは、作成した連携先を選択するとURLを再度コピーできますが、
専用Bearerトークンは初回表示または再発行時にしか取得できません。
再発行すると以前のトークンは無効になります。

## 機能範囲と注意

Dify・n8n・Lancers AI Scout向けの選択肢は**Webhook設定ガイドのプリセット**です。
OAuth接続、ネイティブDify/n8n API連携、GitHub Appの直接イベント購読ではありません。
サーバー上のプロバイダー種別は従来どおり `webhook` / `github_actions` / `rss` のみです。

- Webhook送信先: `POST /v1/inbound/{connection-id}`、`Authorization: Bearer <connection-token>`。
- RSSは公開HTTPSフィードのみで、内部ネットワークのURLなどは拒否されます。最終的なURLおよびDNSの検証はRelay側で行います。
- 連携先の登録にはAndroidのRelay接続先（HTTPS）と暗号化されたクライアントトークン設定が必要です。
- Scoutの遅延が問題になる場合は、既存のSlack並行通知を検証完了まで維持します。
- バックエンドAPI、既存のWebhook ID/トークン、チャット履歴、Room DB、アプリ署名IDは変更しません。

## 実機確認項目

1. 各6プリセットの初期値と4ステップ移動・戻る操作
2. 下書きを残してプロセス再起動 → 続きから再開 → 下書きを破棄
3. 不正RSS URL・空名・空チャンネルで次へ進めない
4. 作成を連打しても二重登録されない
5. 登録失敗時、エラーを表示し下書き保持・再試行できる
6. 成功後、Webhookトークンをコピーしないまま完了できない
7. RSS取得テスト、Webhookテスト通知、チャット画面表示の確認
8. 既存の連携先編集とインポート/エクスポート動作の回帰確認
9. 折りたたみ端末のカバー画面と展開画面でダイアログが読める
