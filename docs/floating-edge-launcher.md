# RelayHarbor v0.9.8 — 画面端フローティングランチャー

Android 8以降のアプリで使える、**完全オプトイン**の画面端ランチャーです。Relayサーバー・NASは不要です。

## 初回設定

1. RelayHarborの **設定** → **サイドフローティングランチャー** を開きます。
2. **他のアプリの上に表示**を許可します。Androidの権限ページが表示されます。
3. 許可したら戻り、機能を有効にします。
4. ハンドルを画面の左右にドラッグし、好みの高さへ移動します。設定画面から左右、縦位置、透明度（40～100％）、サイズ（32～64dp）を調整できます。
5. ハンドルをタップすると、スクショ・ホーム・チャット・通知センター・小窓操作ガイド・設定・停止のメニューが開きます。

機能は**デフォルトでオフ**。権限を与えるだけでは勝手に常駐しません。停止するとAndroidサービスを止めます。再起動後に自動開始するBOOT_COMPLETEDレシーバーは追加していません。アプリ再訪時には保存済みの有効設定があれば復元を試みます。

## スクリーンショット

1. ハンドル→**スクリーンショット**を押します。
2. Androidが表示する**画面共有・録画の同意ダイアログ**で毎回許可します。Android 14以降はトークンを使い回しません。
3. 撮影中はメニューを一時的に非表示にします。撮影が終わると表示を復帰します。
4. Android 10以降では**Pictures/RelayHarbor**にPNG保存され、通知の**共有**から送信できます。Android 8～9ではアプリ専用の画像フォルダーへの保存のみ対応し、共有は利用できません。
5. 同意しなければ撮影しません。Android側が保護する画面の撮影や、許可の省略・強制取得はできません。

スクショ専用のFGS（foregroundServiceType=mediaProjection）を撮影時だけ起動し、キャプチャとPNG保存が終了したら停止します。撮影データをRelay/AIサーバーに送信しません。

## 小窓表示

他社アプリを強制的にワンタップでポップアップ化する公開Android APIはありません。メニューの**小窓表示の使い方**でGalaxy標準のマルチウィンドウ操作を案内します。

Samsung Galaxyの設定（One UI機種により文言が異なります）:
- **設定 → 便利な機能 → マルチウィンドウ** → **ポップアップ表示にスワイプ**を有効
- 目的のアプリの画面上部角から中央方向へ斜めにスワイプ

この段階ではRelayHarbor自身の小窓化やOS全体のタスク管理は含みません。

## 権限・プライバシーと動作上の制限

- **SYSTEM_ALERT_WINDOW**: ユーザーがAndroidの特別な権限画面で明示的に許可した場合のみ使用。普通のアプリの上に小さなハンドルと操作パネルを重ねます。
- **FOREGROUND_SERVICE_SPECIAL_USE**: 常駐ランチャーが有効な間だけ、ユーザーに見える専用通知付きサービスで画面端ハンドルを維持。Play配布ではspecialUseの正当性申告・審査が必要になる場合があります。
- **FOREGROUND_SERVICE_MEDIA_PROJECTION**: スクショ同意後のみ、撮影セッションごとにFGSを開始・即終了。
- **POST_NOTIFICATIONS**: 既存の通知権限を利用します。拒否時もスクショの保存自体は試行しますが、完了通知・共有アクションは表示されない場合があります。
- Androidの背景起動制限、電池最適化、メーカー独自管理、機密画面でのオーバーレイ制限などにより、画面端ハンドルが終了・非表示になる場合があります。バックグラウンドから隠れて起動する手法やAccessibilityを用いた操作の自動化は実装しません。
- RelayHarborが開いていなくても、**有効化中の常駐サービス**が画面端に表示を続けますが、端末の状態により動作の継続は保証されません。常駐に伴う軽微なメモリ・電池消費があります。
- Fold展開/収納で画面サイズが変わった際にハンドル位置を再計算し、画面外に残さないよう制限しています。
- スクショはOSの画面共有画面で指定された対象だけを取得します。ユーザーに無断で撮影せず、端末内のPNG保存以外には自動共有しません。
- オーバーレイはPIN入力や保護アプリ等の機密画面ではAndroidが隠すことがあります。無理に表示させません。

## QAチェック

- オーバーレイ未許可/許可/拒否、オン→オフ、通知から停止、アプリ再起動での設定保持
- 左右へのドラッグ、上下端のクランプ、透明度・サイズ変更
- Z Foldカバー画面・展開画面・縦横回転とタップ領域
- スクショ許可/拒否、Android 14+の1回ごとの同意、PNG保存と共有、スクショへのハンドル写り込み無し、特別に保護された画面
- ホーム/チャット/通知への復帰、他社アプリからの呼び出し
- 常駐サービスの省電力挙動、通知権限なしでの失敗処理
- 実機テストはCIとは別途必要

## v0.9.9 — メニューの閉じ方とオーバーレイを除いた撮影

### 開閉・表示位置の修正

- ハンドルを押してメニューを展開した際、**メニューはハンドルの隣**に表示し、ハンドルを覆わないようにしました。
- メニュー最上部に **「✕ メニューを閉じる」** を追加。ハンドルの再タップでも閉じられます。
- メニューの外側をタップした場合も、Androidから ACTION_OUTSIDE が届けば閉じます。端末によって外側タップが通知されない場合も、閉じるボタンで終了できます。
- 画面が狭い場合はメニューを縦スクロールできるため、Foldのカバー画面や横向きでも閉じるボタンにアクセスできます。
- 「メニューを閉じる」と「ランチャーを停止」は別機能です。前者はハンドルを残し、後者は常駐サービスも終了します。

### フローティング表示を撮影画像から外す

- **RelayHarbor自身のハンドルとメニュー**は撮影の同意画面を開く前にWindowManagerから取り除き、撮影が完了したあとに復元します。従来の View.INVISIBLE による表示切替ではなく、ウィンドウの削除・再作成です。
- ユーザーがAndroidの画面共有同意を拒否・キャンセルした場合、または同意画面を開始できなかった場合も、ハンドルを復元します。
- 取得画像に関わる端末側の描画完了タイミングは実機確認が必要で、Z FoldのOS固有の黒い領域が完全になくなることまでは保証できません。
- **他のアプリが作成したオーバーレイ**をMediaProjectionで強制的に隠すことはできません。Android 14以降では同意画面で「アプリのみ」を選択すると、対象アプリのウィンドウだけが共有され、他アプリの表示が除外される場合があります。ただし画面全体のスクショとは異なり、ステータスバーやナビゲーションバーも含まれません。
- DRM・銀行アプリ等の画面保護領域は、黒く表示されてもセキュリティ上の制約なので解除・復元はしません。

### 検証項目

- 左右それぞれのハンドルでメニューを開閉し、開いたままハンドルが隠れないこと
- 「閉じる」でハンドルが残り、「ランチャーを停止」でサービスが止まること
- ハンドル外タップでの閉じる操作と、ハンドルを連続タップして再表示されないこと
- スクショの許可・キャンセル・拒否後のハンドル復元と画面端の黒い領域
- Z Foldカバー・展開画面、縦横変更、少ない高さでのスクロール
- 端末自身のオーバーレイと第三者のオーバーレイを区別して撮影結果を確認すること

参考：Android公式の MediaProjection（https://developer.android.com/media/grow/media-projection）および WindowManager.LayoutParams（https://developer.android.com/reference/android/view/WindowManager.LayoutParams）。
